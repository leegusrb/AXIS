# 실기기 점검 (아이폰)

같은 Wi-Fi의 아이폰으로 점검한다. 사진 없이 11/22 전에 끝낸다. 결과는 항목마다 체크하고, 어긋난 값은 아래 메모에 적는다.

## 실행 방법

1. 서버를 켠다. 화면 흐름은 `fake`, 방향 확인은 `rule`로 한다.
   - `AXIS_MODE=fake .venv/bin/python -m axis_server --port 8000`
   - `AXIS_MODE=rule .venv/bin/python -m axis_server --port 8000`
2. 노트북 IP를 찾는다: `ipconfig getifaddr en0`
3. 앱의 설정 화면에 `http://<IP>:8000`을 입력하고 "연결 확인"을 누른다.
4. 아이폰을 연결하고 `app/`에서 `flutter run`을 실행한다. Xcode에서 Runner의 Signing에 Apple ID 팀을 먼저 지정해야 한다.

## 점검 항목

### 화면 흐름 (`fake` 모드)

- [x] 홈 → 취향 고르기 → 추천 → "이 스타일로 촬영"으로 카메라 화면이 열린다
- [x] 카메라 권한을 거부하면 안내 문구가 나온다
- [x] 촬영 → 결과 화면(사진, 스타일 이름, "구도 점수 NN점") → 돌아오면 프리뷰가 다시 움직인다
- [x] 홈의 "촬영 기록"에 방금 찍은 사진이 썸네일, 스타일, 점수, 날짜와 함께 나온다
- [x] "가이드 끄기"를 켜면 박스, 화살표, 문구가 사라지고 촬영은 된다
- [x] 서버를 끄면 "서버에 연결할 수 없어요" 배너가 뜨고, 다시 켜면 사라진다
- [x] 앱을 홈으로 보냈다가 돌아오면 프리뷰가 다시 나온다 (빠르게 나갔다 들어와도 "다시 시도" 없이 복구된다)
- [x] 카메라 화면이 가로로 돌아가지 않는다
- [x] 휴대폰을 가로로 기울여도 박스와 방향이 그대로인가

### 안내 방향 (`rule` 모드, 스타일 `thirds_upper`)

- [x] 인물 박스가 프리뷰 속 인물과 겹친다 (겹치지 않으면 아래 "박스가 어긋날 때")
- [x] 인물을 화면 왼쪽 끝에 두면 `LEFT`가 나온다
- [x] 인물을 화면 오른쪽 끝에 두면 `RIGHT`가 나온다
- [x] 멀리서 작게 찍으면 `CLOSER`가 나온다
- [x] 화살표가 0.8초보다 빨리 깜빡이지 않는다
- [x] `OK`일 때 테두리가 초록이 되고 셔터가 강조된다

카메라 화면은 세로 고정이다(`SystemChrome.setPreferredOrientations`). 겹침과 `frameRotationFor`가 세로를 전제로 한다. 가로로 돌려도 화면이 돌아가지 않는지도 확인한다.

## 박스가 어긋날 때

`app/lib/screens/camera_screen.dart`의 `frameRotationFor(CameraDescription)`만 고친다. 지금은 Android면 `sensorOrientation`, iOS면 0이다. 박스가 90도 돌아 있으면 90 또는 270으로 바꿔 다시 확인한다. 고친 경우 Task 11의 프레임 인코더 테스트(`app/test/frame_encoder_test.dart`)에 해당 회전 경우를 추가한다.

- 날짜, 기기, 서버 모드: 2026-11-16, iPhone (iOS 27.2), `rule` 모드 (화면 흐름 포함). 사용자가 앱에서 모든 항목을 확인했다.
- 어긋난 항목과 바꾼 값: 없음. `frameRotationFor`는 iOS 0 그대로 맞았다.
- 서버 기록(`inference_logs`): 프레임 요청 약 140건. 방향 `LEFT`, `RIGHT`, `UP`, `DOWN`, `CLOSER`, `FARTHER`, `OK`, `NO_SUBJECT`가 모두 나왔다. 같은 방향이 3–5번 연속으로 이어져 깜빡임 없이 표시됐다.
